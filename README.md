# Alum 工作台与项目插件

主页为应用工作台，不是博客。Alum4K 作为第一个内置功能模块，保留 TMDB 采集、影视分类、115 网盘链接、磁力链接、用户注册和 VIP 权限管理，不提供在线播放。

## 网站入口

- `/`：Alum 工作台，支持应用搜索、我的常用、最近访问和浅色/深色主题。
- 登录后可使用个人桌面：待办（优先级、截止日期、项目关联、详细备注）、项目进度、便签自动保存、月历与日程。顶部提供到期任务/当日日程摘要，不发送系统后台通知。
- 「编辑布局」启用模块标题旁的拖动手柄，支持鼠标/触屏和键盘排序，模块宽度可选标准或加宽；「添加模块」可恢复隐藏的模块，恢复默认布局不会删除个人记录。
- `/admin`：独立的工作台后台，可修改名称、介绍及模块名称、说明、显示顺序、启用状态。
- `/yingshi`：Alum4K 影视资源站。
- `/yingshi/admin`：影视管理后台。两个后台有互相跳转入口，共用现有管理员账号，不新建或覆盖账户。
- `/windows`：AlumWindows 系统与软件资源仓储。
- `/windows/admin`：AlumWindows 独立后台，共用已有管理员账号。

关闭模块后，前台隐藏入口并停止游客/普通用户访问该模块，模块后台仍可进入，影视数据不删除。工作台本身不受影视站「访问网站需要登录」开关影响。

个人内容保存在 `data/dashboards/`，按登录账号隔离，游客及其他账号不能通过接口读取。自动保存失败时保留当前草稿，可重试或导出 JSON；多标签页/设备同时修改使用版本检查，旧版本不会覆盖新记录，需要先导出并重新载入。没有实时多人协同。请定期备份整个 `data` 目录。

模块清单位于 `plugins/alum4k/manifest.ts`，通用约定位于 `shared/plugins.ts`，配置独立保存于不入库的 `data/workbench.json`。当前是源码内置模块的注册基础，尚不支持上传任意 ZIP、远程安装或执行第三方插件；后续插件化约定见 [插件开发说明](plugins/README.md)。

个人桌面小组件的清单位于 `shared/dashboard.ts`，实现集中在 `src/PersonalWorkspace.tsx`，可在后续版本逐个拆包。当前不包含 AI 服务、浏览器扩展、桌面悬浮窗、文件附件和个人物品管理。

## AlumWindows

参考 [HelloWindows](https://hellowindows.cn/) 的分类与折叠资源布局，初始快照包含其公开展示的 33 个分类、170 条资源和 170 个可见下载入口。资源名称、版本/架构/日期标签、文件大小/哈希等事实字段与公开下载地址保留来源内容；不复制广告、追踪脚本、隐藏链接和宣传说明，不运行来源代码。本站没有逐个下载并验证安装文件，也不表示微软官方认证或提供软件许可证。

下载地址按来源原样保存，其中很多是 `hellowindows.cn/link?...` 中转地址，不是 ISO 文件直链，可能受来源站、网盘及网络状况影响。前台提供下载入口、地址复制、文件信息复制、分类、全文检索、架构筛选、展开/收起、常见问题和深浅色主题。

来源中转链接的加密参数可能在每次请求时变化，因此快照保留采集当时公开的地址，而不是承诺与今后每次访问看到的字符串完全一致。采集不会下载安装文件；安装文件大小和校验值均保留为来源元数据。

后台支持资源增删改、上下架、多条下载链接、分类排序/新增、站点名称/介绍/说明、JSON 导入导出及手动重新采集。重新采集只请求固定的公开来源首页，不接收任意抓取 URL；失败或结构变化不会覆盖本地仓库。合并会更新同来源 ID 的资源，保留手动新增条目、未发布状态和站点设置；替换导入会重建完整清单，操作前请导出备份。

模块清单为 `plugins/alumwindows/manifest.ts`。种子数据 `plugins/alumwindows/catalog.seed.json` 随代码发布，未初始化时离线读取；实际维护数据位于忽略入库的 `data/windows/catalog.json`，写入前保留一份 `.bak`。已有本地仓库不会被新种子覆盖。管理员可在工作台后台关闭该模块；关闭后前台与公开接口停止访问，独立后台仍可进入。

开发者更新发布用快照：`npm run collect:windows`。这不会安装、启动或下载所列软件。界面验证：`PLAYWRIGHT_CHANNEL=msedge npm run test:windows`（PowerShell 先设置环境变量）。

## 本地运行

需要 Node.js 20+。

```bash
npm ci
npm run dev
```

工作台：`http://localhost:5173/`

工作台后台：`http://localhost:5173/admin`

影视前台：`http://localhost:5173/yingshi`；影视后台：`http://localhost:5173/yingshi/admin`。

前台搜索框显示“搜索影视名”，延续精确匹配片名、原名或 TMDB ID。后台 TMDB 搜索支持模糊查询。

## 影视后台功能

后台只允许管理员登录，影视前台导航不显示影视后台入口。

- 媒体库：片名/ID 搜索、分类/资源筛选、分页、批量自动分类和批量删除。
- 影视采集：搜索 TMDB、导入详情、编辑资料、指定首页热播推送、保存或更新 TMDB 元数据。
- 下载资源：115 网盘和磁力链接分开管理，直接粘贴链接或包含链接的分享文字；提取码、大小和备注为独立可选字段。支持新增多条链接，详情页提供两种下载方式及复制按钮。
- 用户/VIP：用户名和会员状态筛选，续期 30 天/90 天/1 年、永久 VIP、自定义到期日、取消 VIP。续期保留已有剩余天数。
- 站点设置：修改网站名称、上传或移除 Logo，选择深色、浅色、石墨灰、森林绿主题；名称和 Logo 同时更新网站导航、后台及浏览器标签页图标。Logo 支持 1 MB 以内的 PNG/JPEG/WebP。
- 首页公告：标题、正文、启停、显示频率以及预览；公告内容变更后产生新版本，仅修改主题或名称不会重复弹出旧公告。
- 管理员账号：在“用户 / VIP”页添加管理员，设置用户名、密码及确认密码；新增管理员密码至少 10 位。普通用户注册不会获得管理员权限。
- 媒体库 JSON 导入/导出：导入支持按影视 ID 或 TMDB ID 更新已有条目，最多 2000 项、10 MB。

每条资源可独立选择“免费查看”或“VIP 查看”，支持同一影视混合配置。免费链接和提取码向所有访客开放；VIP 链接只对有效 VIP 和管理员返回，普通用户的接口响应不包含地址或提取码。旧资源没有独立权限时，继承影视的免费/会员设置；“默认链接权限”控制随后新增的资源。

默认管理员用户名：`admin`。初始密码来自 `.env` 的 `ADMIN_PASSWORD`，开发默认值为 `admin123456`。首次启动后，账号存入 `data/users.json`；此后修改 `.env` 不会修改已有密码。

## 账号与求片

后台“站点设置 → 注册设置”可以开启或关闭“注册需要邀请码”，升级后默认开启。开启时，新用户必须填写管理员生成的 **8 位数字邀请码**（保留前导零），一码一人、使用后失效；后台“邀请码”支持生成、复制和停用。关闭时，前台隐藏邀请码输入框，服务器允许直接注册，也不会消耗邀请码。

新用户注册成功后默认获得永久 VIP，可查看全站资源，但没有管理员权限。已有用户的会员状态不变；管理员仍可在“用户 / VIP”调整会员状态及到期时间。是否需要邀请码由服务器控制，不能通过修改前台请求绕过。

前台右上角“个人信息”可修改名称、头像、介绍和密码，登录账号名保持不变。修改密码需要当前密码；后台“用户 / VIP”可重置普通用户密码。管理员自己的密码由本人在“个人信息”中修改。密码变更后其他登录会话会失效。

登录用户（不要求 VIP）可从右上角“求片”提交电影/剧集需求，查看自己的处理状态和管理员回复。后台“求片管理”可筛选需求、修改状态、回复。每天最多提交 10 条，重复待处理需求不能再次提交；用户不能查看其他人的需求。

免费资源链接与提取码对游客开放，不需要登录；VIP 链接仍由服务端校验，未授权用户只看到资源信息。

## 公告与浏览器信息

后台“站点设置”提供公告与广告管理，可添加、排序、发布/撤下文字、图片和 HTTP/HTTPS 跳转链接。已发布内容出现在前后台公告栏；广告有明确标识。首页弹窗公告设置继续保留。

同页可以设置前台/后台浏览器标题、网站介绍。标题留空时使用网站名称（后台追加“管理后台”）；两边标签页图标使用同一个网站 Logo。头像和公告图片只接受 PNG/JPEG/WebP，浏览器会压缩上传；禁止 SVG 和 HTML 注入。

生产 API 启动及保存设置时，会将前台标题、介绍和 Logo 写入 `dist/index.html` 的指定 head 区域，供 Nginx 返回给搜索引擎；不更改 Nginx、HTTPS 或端口配置。后台设置为不索引，`robots.txt` 排除后台和 API。元数据不保证被搜索引擎收录。

账号、邀请码、求片、站点设置分别保存在 `data/` 内私有 JSON 文件，更新脚本会备份这些数据，且不会提交到 GitHub。

## 自动分类

TMDB 详情采集后，根据类型标签自动归类为电影、电视剧、综艺、动漫、少儿、纪录片。没有足够类型标签时，按电影/剧集区分。短剧、游戏等分类可关闭“自动分类”后手动指定。

媒体库中勾选条目并选择“自动分类”可重新分类已有影视。手动分类的条目保持原分类，除非主动执行批量自动分类。

## 分季与集数

首页保持原有分区和热播展示。其他栏目及搜索结果每页最多两排海报，根据实际列数自动调整每页数量；页码保存在网址 `page` 参数中，刷新、浏览器前后退及从详情返回保留原页。更改栏目、筛选、排序或搜索会回到第一页，超出范围的页码自动修正到最后一页。

前台各栏目采用独立筛选：电影按动作、喜剧、科幻等类型；纪录片按自然、历史、人文、科技等主题；综艺按真人秀、音乐、旅行等节目类型；动漫、少儿、短剧和游戏使用各自题材。筛选兼容中英文常见标签（如 Action 对应动作、Comedy 对应喜剧），并保留媒体库中的自定义标签。后台编辑区可勾选对应栏目分类，原始“类型标签”仍可手工维护；未带主题的纪录片不会仅根据片名猜测主题，可手动补充。切换栏目会重置筛选，刷新和分享网址保留当前选择。

TMDB 剧集详情采集会保存各季的编号、集数、海报和首播日期，默认选择第一季（第 0 季为特别篇）。后台采集/编辑区顶部的“采集 / 编辑季”可在保存前选择本季，点击旁边的加号可手动新增季；“本季集数”和“状态”分别管理每季的信息。手填 TMDB ID 或编辑旧影视时，可点击“加载季信息”读取可选季，不会立即保存，也不会覆盖已填写的链接、标题、权限等字段。“更新 TMDB 并保存”仍可更新整部影视资料，无需重新添加影视。

所有分类均支持集数：电视剧、综艺、动漫、少儿、纪录片、短剧等多集影视，默认状态为“全 X 集”，不局限于“电视剧”分类。分季时使用所选季的集数；不分季时可以在“总集数”填写。没有集数数据时不会猜测数字，单部电影默认“正片”；仍可手动填写“更新至 X 集”等连载状态，更新 TMDB 保留已填写的分季连载状态和下载资源。

后台选季后编辑该季的 115 网盘和磁力资源，新链接默认绑定当前季，每条链接的“所属季”也可手动调整。旧链接保持为“通用 / 合集”，各季均可看到，不会被自动归入第一季；其他季的链接在切换编辑时完整保留。同一个合集链接可以分别绑定不同季，免费/VIP 权限独立生效。

前台详情页的“选择季”会切换对应资源、集数及状态，通用链接同时展示。选季记录在详情网址的 `?season=编号` 中，刷新或分享后仍定位到相同季；切换季不会绕过 VIP 权限。JSON 导入/导出包含 `seasons`、`selectedSeason`、`episodeCount` 和资源 `seasonNumber`。

## 配置

首次运行复制 `.env.example` 为 `.env`：

```dotenv
TMDB_BEARER_TOKEN=
TMDB_API_KEY=
API_PORT=5174
ADMIN_PASSWORD=设置管理员初始密码
AUTH_SECRET=随机长字符串
HTTPS_PROXY=
HTTP_PROXY=
```

TMDB 令牌和代理只在服务端使用。AList 不再参与播放，旧的 AList 路径不作为下载资源展示；有效的 115 分享链接和磁力链接会继续保留。

下载资源无需分隔符格式，直接粘贴：

```text
https://115.com/s/分享码
magnet:?xt=urn:btih:完整哈希
```

输入内容原样保存、显示和复制，不检查域名、磁力格式或链接是否有效，也不自动提取或改写分享文字。支持多行说明，提取码仍可填写在独立字段；每项最多 10000 字符，每个条目最多 500 条资源。普通文字和不安全的协议仅显示为文本，不作为可点击链接；免费/VIP 权限不变。

详情页的每条资源以紧凑两行显示：第一行是可点击的资源名称（没有自定义名称时显示链接），右侧提供复制和反馈按钮；第二行是大小、画质、更新时间，附带可选的提取码、字幕、音轨和备注。普通分享文字始终原样显示。大小与画质来自后台“资源详情”，不自动检测；更新时间由服务器保存时维护，前台以北京时间日期 `YYYY-MM-DD` 显示。

## Linux 部署

后台“站点设置 → 免责声明”可编辑页脚正文，最多 3000 字，支持换行。正文以纯文本显示在所有前台页面底部右侧，留空则隐藏；管理员页面不显示前台页脚。

先安装 Node.js 20+，在可被 Nginx 读取的目录部署，例如 `/opt/alum4k`：

```bash
git clone https://github.com/Alumchen/alum4k.git /opt/alum4k
cd /opt/alum4k
cp .env.example .env
nano .env
sudo env SERVER_NAME="alum4k.com www.alum4k.com" bash scripts/deploy-linux.sh
```

脚本安装依赖、构建前端、创建 systemd 服务和 Nginx 配置，将 `/api/` 代理至本机 5174 端口。自定义首次部署端口：

```bash
sudo env WEB_PORT=8080 bash scripts/deploy-linux.sh
```

**已有 Nginx 和 systemd 配置会保留，包括 HTTPS 证书、域名及 1023 等自定义端口。** 修改现有端口或域名应直接编辑 `/etc/nginx/sites-available/alum4k.conf` 并检查/重新加载 Nginx。两个后台使用同一域名，不需要开放额外端口；旧影视后台 `/admin` 现为工作台后台，影视后台请改用 `/yingshi/admin`。

## 更新线上网站

在云服务器终端执行：

```bash
cd /opt/alum4k
sudo git pull --ff-only
sudo bash scripts/update-linux.sh
```

只有上一条命令成功后才执行下一条。如果 Git 提示本地修改冲突，先保留现场，不要使用强制重置。

更新脚本会在 `backups/时间戳/` 保存 `.env`、`data`、已有前端构建、Nginx 和 systemd 配置；构建成功后重启 API 并重新加载 Nginx，不重写现有证书配置。构建失败时恢复原前端文件，不重启后端。

更新脚本不会覆盖用户、VIP 和公告数据。备份目录权限为仅部署用户可访问，不会提交到 GitHub。请定期把备份另存到服务器之外。

常用命令：

```bash
sudo nginx -t
sudo systemctl status alum4k
sudo journalctl -u alum4k -f
sudo systemctl restart alum4k
```

## 资源、详情网址和搜索

### Windows 115 磁力收集器（半自动）

当前版本不自动点击、翻页或匹配 TMDB。它只在指定的 115-Desktop 程序处于前台、剪贴板发生新变化时提取完整的 40 位 SHA-1 BTIH 磁力，忽略启动前已有内容和其他剪贴板文本，不读取登录文件，不上传到网站。安装目录不会被修改。

在项目根目录运行 `npm run collect:115 -- --title "影视名" --year 2026`，或双击 `scripts/115-collector/launch.cmd` 后用 `/title 影视名`、`/year 2026` 设置当前影视，再回到 115-Desktop 点击各资源的「复制链接」。默认程序位置为 `G:\115-Desktop\115-Desktop.exe`，可用 `--exe` 指定其他位置。只复制链接，不会触发「添加到115」或下载。

记录自动保存到 `data/115-collector/`（不提交 GitHub）：`collection.json` 为完整采集记录，`magnets.txt` 为去重后的磁力，`library-import.json` 为已填写片名的媒体库导入草稿。未填写片名的链接保留待整理，不猜测归属。年份、资源名称、大小、画质需要手动填写；`collectedAt` 只是采集时间，不当作资源原始更新时间。草稿链接默认 VIP，导入前在后台预览、核对类型和片名，避免与已有 TMDB 条目重复；不会自动合并到已有 TMDB 影视，也不会上传网站。再次导入相同采集 ID 会更新对应条目及其资源，手动补充过的资料应先备份再核对。

控制台支持 `/title 新片名`（同时清空旧年份和资源描述）、`/year 年份`、`/resource 资源名称`、`/size 50 GB`、`/quality 2160p / 4K`、`/status`、`/export`、`/quit`。切换片名后只影响新复制的链接，已有重复磁力不会自动改归属。剧集可启动时指定 `--category 电视剧 --type tv`；单部纪录片可指定 `--category 纪录片 --type movie`。Ctrl+C 正常退出后可重新启动续采；异常断电后若提示锁文件，应先确认所有收集器已退出，再处理提示的 `.collector.lock`，不要删除 `collection.json`。

也可用 `npm run collect:115 -- --input "本地磁力.txt" --title "影视名" --year 2026` 整理不超过 10 MB 的本地 TXT，此模式不启动剪贴板助手。`--output` 可选保存目录，`--duration` 可设置测试运行秒数。保持收集器窗口打开并在 115 软件里操作；它不会后台自动扫描整个资源库。

### 检测通过后自动上传

默认收集模式不变。新增的自动上传模式仍需要在 115-Desktop 手动点「复制链接」，之后自动完成检测和上传，不会自动点击或翻页。仅整理你有权使用、发布的资源。

1. 先更新服务器，启用新的管理员采集接口：

   ```bash
   cd /opt/alum4k && sudo git pull --ff-only && sudo bash scripts/update-linux.sh
   ```

2. 在运行收集器的电脑安装 [aria2 官方发布版](https://github.com/aria2/aria2/releases)。确保 `aria2c --version` 可运行，或放到 `data/115-collector/tools/aria2c.exe`，或在以下命令追加 `--aria2 "aria2c.exe的完整路径"`。Linux 可安装发行版的 aria2 包。只下载种子元数据，不下载影片本体；检测需要外网 DHT/UDP 能力，防火墙或网络限制会造成无法确认。
3. 本机项目终端运行 `npm run collect:115:login -- --site https://www.alum4k.com`，输入管理员用户名和密码（密码不回显、不保存）。会话只保存在忽略提交的 `data/115-collector/site-session.json`；不要分享此目录。网站拒绝会话或密码变更后需重新登录。仅允许 HTTPS，localhost 测试除外，重定向不会携带会话转发。
4. 开始采集，例如：

   ```powershell
   npm run collect:115 -- --auto-upload --title "准确影视名" --year 2024 --timeout 60
   ```

   多季影视加 `--category 电视剧 --type tv --season 1`；已有影视也可用 `--media-id 后台影视ID` 指定归属（类型仍需正确）。控制台 `/target`、`/season`、`/date` 分别设置目标影视、季数、源站日期，留空清除；切换 `/title` 会清空旧目标、季数、日期，避免错绑。

已有记录可运行 `npm run collect:115:sync` 逐个检测上传。参数 `--title`、`--year`、`--type`、`--media-id`、`--season`、`--source-date` 可对本次全部待同步记录覆盖，务必只对属于同一影视的一批记录使用；不会改写原始收集文件。目录锁避免同步和收集同时运行；成功记录断点跳过，未确认/失败记录下次可重试。报告保存在 `upload-report.json`，不要使用旧的 `library-import.json` 草稿绕过检测自动入库。

判定标准：实际从网络取得种子元数据，并解析校验 infohash；错误格式、哈希不匹配、元数据过大拒绝，超时、无节点、网络错误一律「无法确认」且不上传。**取得元数据不代表保证完整影片可下载、文件内容真实或以后一直有效**。不读取浏览器/115 登录资料，不把 `xs`、web seed、任意 tracker URL 交给检测器；此保守 DHT 检测可能跳过私有或暂时无节点的有效资源。网站只接受近期元数据证明，并再次校验哈希；这不是独立的服务器实时探活或永久可用承诺。

归属匹配必须是片名（含原名/别名）、年份、movie/tv 类型唯一匹配；已有条目仅追加磁力，不覆盖海报、简介、旧资源及权限。没有本地匹配时，使用服务器 TMDB 精确匹配并采集完整资料；缺少 TMDB 配置、歧义、季数不明确时不入库。资源默认 VIP，以「种子名称在上，大小 / 画质 / 日期在下，右侧复制按钮」展示；大小来自种子总字节数（十进制 GB），画质从种子名称识别，无法识别时不编造。原始复制内容只有 magnet 时不包含截图中的日期，需 `--source-date 2026-10-14` 或 `/date` 手动提供；否则日期为网站实际入库时间。

这套检查仅用于收集器自动上传流程，不限制后台手工录入任意链接或文本。

### 自动补充已有影视的磁力

先完成上面的服务器更新和本机管理员登录。若已有采集记录，运行：

```powershell
npm run collect:115:backfill
```

边复制边补充则运行 `npm run collect:115 -- --backfill`，再到 115-Desktop 中复制资源磁力。此模式不必逐条输入片名或 movie/tv 类型：取得种子元数据后，按名称前缀匹配网站已有的片名、原名、别名（兼容点号、空格、下划线分隔），结合年份消除同名歧义；剧集从 S01 / 第1季 识别已有季数。单季条目可自动绑定唯一一季，多季不明、季数冲突、合集跨季或多个可能匹配均跳过，支持 `--media-id` / `--season` 人工明确归属。

补充模式使用独立接口，**绝不调用 TMDB 新建影视**。已有磁力的影视仍可追加不同 hash 的版本；相同影视同一季的重复 hash 不再新增，不替换旧链接、简介或海报。每条仍需通过元数据哈希检测，超时或无法确认不上传；成功/失败继续记录到 `upload-report.json`，重跑可重试未成功项。原始磁力本身没有片名等资料且不能解析时无法匹配，不会凭空搜索整个 115 资源库或生成磁力。

首页入口使用加载状态，不再输出开发服务器提示。脚本加载失败时最多自动重试一次（60 秒内不重复），持续失败显示手动重新加载；弱网等待超过 20 秒也可手动重试。Linux 更新先构建到独立临时目录，再复制新资源、原子切换入口，保留旧的哈希脚本供已打开的页面使用。更新脚本为 HTML 添加重新验证缓存，为 `/assets/` 添加长期缓存、真实 404 和 JS/CSS 压缩，保留已有端口、HTTPS 和自定义缓存配置。

TMDB 海报、背景图与后台缩略图按显示尺寸使用同站点 `/api/images/tmdb/` 图片缓存，首排/热播图片优先加载，其余懒加载。缓存位于 `data/cache/tmdb-images/`，默认上限 256 MB，可通过 `.env` 的 `TMDB_IMAGE_CACHE_MB` 设置 32-2048 MB；缓存超过上限自动清理旧图。浏览器缓存有效期 7 天，支持 ETag，服务器重启后仍复用磁盘缓存。服务器首次获取图片仍依赖 TMDB 的网络速度，必要时沿用 `HTTPS_PROXY`；缓存加载失败会尝试原图，不代理自定义图片站点或任意网址。

影视后台「站点设置 → 访问设置」可开启「访问网站需要登录」，默认关闭，旧站点配置自动沿用关闭状态。开启后，游客访问影视首页、分类或详情先显示居中的独立登录/注册页；登录或注册成功进入原网址，退出或登录失效后回到登录页。影视接口也要求有效登录，免费/VIP 链接仍遵循原权限；注册及两个后台不受影响。私有模式不输出影视 SEO 内容和影视站点地图，只禁止收录 `/yingshi`，工作台仍公开。关闭开关后恢复游客访问；该设置不改变邀请码要求。

首页展示热播剧集、热门电影、热门动漫三个分区，对应电视剧、电影、动漫分类，不展示综艺分区（侧栏综艺分类保留）。每区最多两排海报，数量随屏幕宽度调整，按影视的更新时间（无更新时间时使用创建时间）倒序排列。分类页和搜索结果保留组合筛选。前台不显示公告横条，顶部公告图标和已启用的首页弹窗仍可查看公告，后台公告栏不受影响。

首页最上方的“正在热播”轮播只展示管理员推送的影视。后台“媒体库 → 编辑影视”勾选“首页热播推送”并保存即可加入，取消勾选后撤下；已有的“首页推荐”设置自动沿用。推送按影视更新时间倒序排列，没有推送时不显示轮播。支持上一部、下一部、分页选择、暂停及手机滑动；默认每 6.5 秒切换，鼠标悬停、键盘聚焦及后台标签页自动暂停，系统减少动态效果时默认暂停。轮播仅进入详情页，不提供在线播放，也不绕过资源权限。

前台“求片”旁的太阳/月亮图标可切换浅色和深色背景，文字和控件颜色同步变化。选择保存在当前浏览器，刷新后仍保留，不改变后台设置或其他访客的主题；未主动切换时使用管理员设置的默认主题。顶部栏与页面背景一致；左侧菜单在悬停、键盘聚焦和选中时突出显示，尺寸不变，避免挤动其他菜单项。

后台“站点设置 → 注册设置 → 注册提示文案”可编辑注册界面的活动说明，最多 500 字；留空则不显示。原有默认文案“限时免费送7天体验会员，联系微信dkiss_zhou领取激活码。”继续保留，可按实际活动修改。提示文案仅用于展示，不决定会员期限；新注册用户默认获得永久 VIP。

后台编辑影视时，展开每个链接的“资源详情”，可填写分辨率、动态范围、视频编码、字幕和音轨。资源输入无需核验；更新时间由服务器维护。115 链接复制时会同时附带独立字段填写的提取码。保存尚未入库的 TMDB 草稿或已删除的旧编辑条目时，会自动新增；如果同一 TMDB 影视已经存在，会合并更新已有条目而不是创建重复记录。

用户可在有权限查看的资源旁提交“失效反馈”，游客也能反馈免费资源。后台“资源反馈”支持筛选、处理说明、编辑对应影视，以及处理时标记链接失效。状态仅作后台记录，不阻止前台显示、打开或复制；反馈期间已经更换的链接不会被旧反馈误标记。单用户或游客来源每天最多提交 10 条反馈，同一资源的待处理反馈不能重复提交。

影视拥有固定详情网址 `/yingshi/movie/内部ID` 或 `/yingshi/tv/内部ID`，支持刷新、分享和浏览器前进/后退。原 `/movie/内部ID`、`/tv/内部ID` 永久跳转到新地址，保留选季参数；旧根路径的分类书签请改为 `/yingshi?category=分类`。后台“站点设置”的“网站地址”仍填写域名根地址 `https://www.alum4k.com`，不要追加 `/yingshi`。`/sitemap.xml` 为工作台与影视地图的总索引，影视地图位于 `/yingshi/sitemap.xml`。详情 HTML 不包含受保护的下载链接。

搜索提交仍为精确片名、原名、别名或 TMDB ID 匹配；输入时可选择片名联想。后台影视编辑中可以填写别名，一行一个。年份、评分、资源状态、类型、地区和免费/VIP 筛选可组合使用，筛选条件保存在网址中。搜索无结果时可直接提交求片，登录后会带入搜索片名。

更新脚本会在现有 Nginx 配置中增加详情页、地图和 robots 的后端代理规则，保留原有 1023 等端口、域名和 HTTPS 设置，并在重新加载前执行 `nginx -t`。如已有自定义同名路由，脚本会停止并提示手动合并，不会强制覆盖。
